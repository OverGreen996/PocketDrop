## 桌布測試步驟

1. 記住原桌布與設定。從 Windows 設定 → 個人化 → 背景，選擇本專案 `fixtures` 的 PNG；用「填滿」即可。不要拿 CSS background、網頁預覽或固定截圖當桌面玻璃。
2. Widget 背後不要有其他視窗。先記錄 Acrylic API 狀態，再移動到不同區域；分別截圖 G02 三個位置。
3. 同一位置關閉原生模糊再截圖，保留相同文字模式與位置。
4. 深、亮桌布分别測試，保留 `◐` 模式記錄。細字不可消失於亮背景。
5. 測完恢復原桌布。若視覺只呈固定灰色，填 **FAIL**，不是「大致通過」。

## Windows 差異與明示處理

| 環境 | 上游／API 條件 | 本原型處理與驗收 |
|---|---|---|
| Windows 10 <1809 | Acrylic 不支援 | 不在支援範圍；原生 API 失敗明示 |
| Windows 10 1809+ | 可呼叫 Acrylic；1903+ 有已知拖動/縮放效能問題 | 未實測，不承諾可接受 |
| Windows 11 build 22000 | 上游記載 Acrylic 拖動效能問題 | 未實測，必須量測 |
| Windows 11 22621+／26200 | 有原生 Acrylic 路徑，但版本與驅動可能影響效果 | 本輪僅實際測到的 build 可填結果，不能外推 |
| 關閉透明效果／節能／RDP/VM | compositor 可能禁用或改變材質，API success 不代表透明 | 標成不符合／待測；可人工選「關閉」做診斷，不當作玻璃 fallback |
| Mica | 材質語義不同，不能保證局部背景即時取樣 | 本原型不用 Mica |

本原型不會自動截圖桌布，也不會自動切到固定灰底假裝原生成功。若 API 返回成功但系統把 Acrylic 變成實心，本輪仍需要肉眼與 A/B 判斷，**尚無自動偵測**。若特定系統無法達標，應保持驗收不通過，討論替代原生實作後再做 M0。

參考：[Tauri 視窗設定與版本註記](https://v2.tauri.app/reference/config/)、[window-vibrancy 官方說明](https://github.com/tauri-apps/window-vibrancy)、[Acrylic API 限制](https://docs.rs/window-vibrancy/0.6.0/window_vibrancy/fn.apply_acrylic.html)。
